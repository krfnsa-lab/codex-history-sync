# 兼容范围与回归检查

2.2.4 补充原生压缩归档：索引指向 `.jsonl` 而相邻 `.jsonl.zst` 保存正文时，通过标准库或 backports.zstd 逐块读取逻辑字节，不更改归档。解码窗口上限 128 MiB，不保证支持更大窗口、需要外部字典或未知扩展格式的归档。缺少解码器、压缩损坏和读取期间变化均暂缓并报告；明文和压缩同时存在时以索引所指明文为准。

## 记录处理

- 支持原生头部的 `timestamp`、`ordinal` 和其他完整的小型元数据字段，不依赖这些字段的固定排列。只从顶层头部读取 `type`，不把正文或嵌套对象中的类型当成整条记录类型。
- 对头部可识别的普通消息、图片及 `compacted` 历史记录逐块复制，正文原字节保持不变；不因正文超过环境记录限制而截断或丢弃。
- `session_meta`、`turn_context` 等环境记录继续使用 8 MiB 解析上限；实际环境记录超限和无法识别的大记录头分别报告原因。未知结构保守停止该记录，不扩大内存限制来碰运气。
- 环境路径映射、缓存字节偏移、精确版本检查、目标备份、提交回执和基线保存继续执行原有保护。缺失记录结尾、未知工作目录及版本变化不能被重试绕过。

## 零传输与重试

自动检查在零传输后保留五分钟重试间隔，避免反复暂停和重载；提示保留上次未同步的具体原因及剩余时间。缓存只保存允许的原因代码与数量，不保存聊天 ID、标题、正文或任意错误文本。

用户手动检查可以立即重新核对。它仅跳过时间冷却，仍需通过后端健康、60 秒空闲、唯一窗口、未保存文件、调试、草稿确认、版本与导入保护。成功提交后清除旧的冷却诊断；诊断存储失败不能把真实成功传输改报失败。

## 本次实证

- 使用实际被拒绝的 26,362,476 字节记录导出包，在独立的 Windows 与 WSL 原生数据库目录中测试。
- 正向与反向各提交一条；每次随后重复运行均传输零条。来源记录未改动，消息缓存内容和标识保留，基线与原生回执吻合，没有未完成导入。
- 真实聊天目录仅用于原生只读导出和结构读取；未复制认证、未调用模型。隔离数据目录在验证后清理。
- 合成回归覆盖超过 8 MiB 的压缩记录、额外头字段排列、嵌套类型、转义类型、真实环境上限、分块读取和残缺尾部，以及双向完整导入和缓存偏移。

本次没有证明用户前台窗口的视觉刷新、图片显示或所有历史聊天均已一致。界面仍须以实际提交数量报告结果；未知格式应给出可检查的原因，而非反复宣称成功或只提示等待。
