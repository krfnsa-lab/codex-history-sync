# 查看同步进度

同步脚本 2.2.0 与可选 VS Code 插件 1.1.0 提供三种进度显示。升级后保存代码和未发送草稿，重新加载一次 Remote WSL 窗口，加载新版插件。

## 状态栏、通知与详情

自动检查期间，右下角 Codex 状态显示正在执行的阶段和已用时间，例如：

```text
Codex：检查 Windows 记录 · 3 秒
Codex：扫描记录 · 8 秒
Codex：备份原记录 · 第 2 条 · 16 秒
```

手动检查会同时显示右下角进度通知。点击正在运行的状态栏不会再发起重复检查，而是展示当前进度并打开输出面板。按 F1 运行 **Codex History: Show Sync Progress** 也能查看 **输出 → Codex History Sync**。没有任务在运行时，命令显示本窗口保留的最近详情，不会启动同步。

详情在阶段或数量变化时追加记录，例如：

```text
比较两端记录 · 已处理 0/3 条 · 已同步 0 条，暂缓 0 条
备份原记录 · WSL · 已处理 1/3 条 · 已同步 1 条，暂缓 0 条
等待安全同步条件：部分记录暂缓处理 · 已处理 3/3 条 · 已同步 2 条，暂缓 1 条
```

以上为显示格式示例，具体阶段、数量和等待原因取决于实际运行；不是预先安排的进度动画。详情仅保留有上限的近期记录。

## 如何理解数量和等待

- **已处理**：本轮已经检查并完成本次处理的聊天，可能已同步，也可能因安全条件不足而暂缓。
- **已同步**：已取得真实导入回执并完成同步状态保存的聊天。
- **暂缓**：仍等待空闲、后端停止、工作目录映射、冲突选择或下一批处理的记录。不会据此宣称两端全部一致。
- **记录计数**：端点能确认扫描范围时显示实际已读取数量；它不是聊天轮数，也不表示已完成写入。

只有准确总数可用时显示数量比例。扫描、单条备份和其他未知耗时步骤显示阶段与用时，不按经过时间推算百分比。暂停与重载仍沿用原来的草稿确认、安全检查和导入保护。

超过 30 秒没有新的阶段或原生心跳时，界面显示 **“等待进度更新，尚未确认同步结果”**。这可能是较慢的阶段、互操作延迟或进程异常，不能单凭停更判断任务成功或失败。终态为等待或错误时会保留相应提示，不显示完成全部同步。

定时任务已经运行时，手动检查可转为查看该任务的新鲜进度；无法发现或继续确认进度时提示稍后重新检查。昨天的完成文件、另一轮运行或另一端操作的明细不能完成当前界面任务。

## 资源与隐私

控制器在既有同步锁内写 `runtime/progress.json`；每次原生端点调用写 `runtime/progress-detail.json`。文件使用运行和操作标识关联，原子替换以避免读到半个 JSON。同阶段最多每秒落盘一次，阶段切换和终态立即写入。

插件只在当前检查、同步或观察正在执行的任务期间每秒读取小型进度文件，结束后停止；不新增常驻服务，也不每秒启动 Python 或扫描聊天库。进度文件不含聊天标题、正文、个人路径、任意异常文本或凭据。进度显示或文件写入失败不会授权覆盖、清除未完成导入或改变同步结果。

`-DryRun` 和 `-Initialize` 保持原有语义，不生成进度文件。运行目录和基线仍需在升级时保留，不要将进度文件作为恢复导入的依据。
