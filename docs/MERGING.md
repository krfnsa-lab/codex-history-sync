# 旧合并任务恢复

当前插件使用[手动选择 Windows 或 WSL](CONFLICTS.md)，统一同一条聊天，不创建合并副本。旧版本已经生成的副本、原聊天和完整备份仍保留；升级不自动清理任何聊天。

若旧合并曾在一端导入成功、另一端中断，保留运行目录中的 `merges/<job-id>` 和 `pending.json`。仅针对同一个旧任务运行：

```powershell
python .\merge_chat.py --controller .\history_sync.py --config .\config.json --resume <job-id>
```

恢复核对原生验证报告、包哈希、新聊天 ID 及已提交端的精确回执，只补齐未提交端。已导入副本后来续聊、缺失回执或身份不符时停止，不覆盖已有聊天。不能通过删除 pending 绕过恢复。

`history_merge.py` 与 `merge_validate.py` 保留为旧任务使用的离线工具。它们处理完整导出包和隔离原生验证，不是当前插件的冲突处理策略。旧合并包保留完整两端源包、共同前缀与各端分支；分叉后的压缩记录仅从派生副本移除，原始包保持完整。

聊天包、验证副本及运行报告都含私有数据，不得加入公开仓库或发布包。公开发行仅含代码、合成测试和说明。
