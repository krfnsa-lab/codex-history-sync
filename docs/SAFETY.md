# 同步保护与兼容边界

首版用于 Windows 原生 CPython 与 WSL 原生 Python，两端均要求 3.11 或更新版本。协调器由 Windows 运行；端点分别在自己的系统中打开当地 SQLite。数据库结构按字段检查，支持当前 `state_5.sqlite`、`thread_history_1.sqlite` 和会话 JSONL。其他数据格式需要新增适配和合成测试。

## 同步规则

- 默认只处理来源为 `cli` 或 `vscode` 的普通交互记录。
- 两端保存各自的原生内容指纹与元数据指纹，避免系统路径差异造成循环同步。
- 默认单侧发生变化时传输；同一聊天两侧均变更时保留双方并报告冲突。
- 可选 `conflict_resolution=prefer_longer`：对已跟踪的双方副本先比较轮数，再比较内容条目数，先备份目标旧版本后替换。数量相同、缺失或不完整时保留双方；不自动合并。目标独有消息保留在备份里。
- 尚未建立双方基线的初始正文差异受到保护。已有跟踪基线的正文差异默认需人工处理，显式启用上述策略后可按数量选择版本。
- 删除不自动传播，也不自动重建已消失的副本。
- 只复制已缓存的正文；旧 JSONL 有消息却没有可迁移正文索引时，跳过并要求单独恢复。
- 源或目标未达到静默时间、正文缺失或末行未写完时暂缓。
- 更新已有目标记录前，检查目标系统所有原生 Codex 进程；检测失败时保守暂缓。

## 数据与路径

每端只接受本地数据目录。WSL 不允许通过 `/mnt` 打开活动 Codex 数据库；Windows 拒绝 WSL UNC 路径。正文路径须属于当前数据目录的 `sessions` 或 `archived_sessions`；越界或指向另一系统的记录只报告，不自动改路径。

不复制登录凭据、Codex 配置、插件或原生迁移表。已有目标聊天保留当地项目、侧栏和数据库权限字段；新增聊天的数据库权限使用保守默认值。继续执行代码前应打开实际项目并检查目录。

会话 JSONL 中的历史权限对象保持原值；不会把其中的消息文字或工具参数当作路径转换。2.0.2 导入时仅调整 `session_meta` / `turn_context` 的 `cwd`、`runtime_workspace_roots`、`workspace_roots`。盘符目录与 `/mnt/<drive>/` 映射到相同目录，不接受盘根、系统根、UNC、相对路径或路径跳级作为自动映射的工作区根。工作目录必须可映射且在目标端存在，否则拒绝导入；不可用的额外根目录移除，不回退到用户目录或整盘。

上述为默认项目同步规则。2.3.0 的 `windows_history_view_only=true` 是单独主动启用的历史查看配置：只对 WSL → Windows 的完整导入改用数据目录内每条聊天独立的空目录，清空运行工作区根，将历史运行环境及目标数据库权限设为只读、审批 never，并移除目标项目绑定。完整原始导出保存在私有备份的 source-package 中，消息文字、工具输入及缓存 JSON 不变。它不映射 WSL 项目，不禁用官方客户端发送框，不保证控制用户之后主动更改权限；继续操作项目应回到 WSL。查看版正文不能反向覆盖原项目，后续 WSL 更新和元数据同步仍受精确版本及原有导入保护约束。

`repair-paths.ps1 -DryRun` 只预览原生路径字段。实际修复须停止目标端 Codex 后端，并使用现有聊天自己的精确版本和原始正文包；仅改环境路径及对应字节偏移，不删除重建缓存行，保留本地关联字段和聊天元数据。修复前备份原基线及每条聊天。修复前已有的本地编辑继续对照旧基线，避免修复把待同步内容当作已同步。

正文通常按记录处理；较大的普通消息流式复制。需要解释的环境记录或无法识别布局的单条记录超过 8 MiB 时拒绝操作，保留原数据。

JSONL 哈希、复制及缓存正文读取尽量采用流式方式。SQLite 连接、索引和单条结构字段仍会使用内存，不能保证恒定内存。每轮初始完整指纹扫描尚未分页；超出软预算后不再开始新传输。

## 中断与备份

控制器在导入前写入运行目录的 `pending.json`，目标目录下 `.history-sync-backups/` 保存原文件、原缓存及导入日志。只有验证到精确提交回执并写入基线后才删除控制器的 pending。

部分成功后发生普通异常，运行摘要仍记录已完成检查点的数量；目标在提交后的新修改不会被吞进当前基线。异常会尽量回滚当前聊天，但数据库和 JSONL 不能作为跨数据库、跨文件的单一原子事务。

强制终止、断电或跨数据库提交中断，可能需要人工恢复。存在控制器 pending 或目标 pending 备份日志时，自动写入停止。应保留两端记录、基线、日志和备份；本版没有自动恢复、自动正文合并或自动删除 pending 的命令。

日志不保存聊天正文或凭据。临时包和备份包含正文；临时包正常结束后删除，备份不自动清理。配置、日志、基线、备份和真实数据均不进入公开发布包。

## 调度和升级

任务以当前登录用户普通权限运行，不存储密码，不唤醒电脑。一次检查结束后退出；多个触发重叠时忽略新触发，进程锁还保护手动与计划任务重叠。

可选 `auto_exit_windows_for_wsl_choices=true` 只为已确认且版本未变化的 WSL 手动选择自动退出 Windows Codex；默认关闭。先正常退出，随后结束核验过的同用户、同会话残留 Codex 进程，再重新检查版本和目标后端。不读取未发送草稿，不保证草稿保留；不适用于同时使用两端。完整触发条件和退出限制见[手动处理冲突](CONFLICTS.md#自动退出-windows-后端)。

普通单端 WSL → Windows 更新可另行启用 `auto_exit_windows_for_wsl_updates`；同样不适用于同时使用两端。只解除规划阶段的 Windows 进程标记来判断候选，所有真实导入继续检查后端已停止、双方空闲、精确版本和目标备份；不选择双边冲突的保留版本。退出时写回新内容会阻止按旧状态覆盖。

WSL 端点调用前检查发行版是否运行，以避免唤醒停止的 WSL。检查和调用之间仍有极小竞争窗口；WSL 若恰好在此时被外部关闭，Windows 的 WSL 调用可能重新启动它。此处没有 OS 提供的原子“仅在运行中执行”接口，不能将检查描述为绝对保证。

任务所有权依据项目目录、配置文件、运行目录、动作和描述共同核验，拒绝覆盖其他配置的同名任务。升级或移动目录须先卸载原任务、等待本轮结束、保留配置及运行目录，再重新安装。已有个人部署与本公开版应按独立配置处理，不自动接管另一目录的任务。
